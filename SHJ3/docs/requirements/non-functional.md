# 7. Non-functional requirements

Tenant-isolation security requirements are `NFR-SEC-15` to `NFR-SEC-25` and are set out separately in [`tenant-isolation.md`](./tenant-isolation.md).

## 7.1 Security — `SEC`

| ID | Requirement | Source | Pri | Acceptance criteria |
|---|---|---|---|---|
| NFR-SEC-01 | All authorisation shall be deny-by-default and evaluated server-side in the inbound adapter; a client-side check shall be treated as presentation only. | architecture §9, §10 | MUST | Every route in the route table has a server-side check, verified by an exhaustive test that calls each route unauthenticated and under-privileged. |
| NFR-SEC-02 | Secrets shall exist only as environment configuration supplied by the platform secret store, never in code, configuration files, container images, Helm values, logs, error messages or documentation. | architecture §10; ADR-0008 | MUST | A secret scanner over the repository, the built images and the chart finds nothing. Log output for a failed external call contains no credential. |
| NFR-SEC-03 | All external and internal service-to-service traffic shall be encrypted in transit, with `shj3-web` → `shj3-ai` using mutual TLS in cluster. | architecture §2 | MUST | Plain-HTTP requests to either runtime are refused in cluster. The AI service rejects a caller without a valid client certificate. |
| NFR-SEC-04 | Network policy shall permit only `shj3-web` to reach `shj3-ai`, and only `shj3-ai` to reach Neo4j and Qdrant. | ADR-0008 | MUST | A pod outside the allowed set cannot open a connection to `shj3-ai`, Neo4j or Qdrant. The web pod cannot resolve a connection to the derived stores. |
| NFR-SEC-05 | All input crossing a trust boundary shall be validated against a declared schema before use, and the same schema shall validate on the client and the server. | architecture §9 | MUST | Every route handler validates with a shared schema. A payload violating the schema is rejected with a 4xx before any domain logic runs. |
| NFR-SEC-06 | Retrieved document content and user uploads shall be treated as untrusted and shall pass the prompt-injection filter before entering a model prompt. | B12 tab 1; [`governance.md`](./governance.md) FR-GOV-04 | MUST | An injected instruction in a retrieved passage does not change agent behaviour and is recorded as blocked. |
| NFR-SEC-07 | The system shall rate-limit authentication, citizen turns, outbound sends and tool invocations per principal and per tenant, failing closed with a distinguishable error. | ADR-0006 rule 4; [`tools.md`](./tools.md) FR-TOOL-11 | MUST | Each limit is configurable, enforced, and observable. Exceeding a limit returns 429, not a slow success. |
| NFR-SEC-08 | Container images shall run as a non-root user with a read-only root filesystem and shall contain no build toolchain. | ADR-0008 | MUST | Both images run as a non-root UID, cannot write outside declared volumes, and contain no compiler or package manager in the runtime layer. |
| NFR-SEC-09 | Base images shall be pinned by digest, and every image shall carry a version label traceable to a commit. | ADR-0008 | MUST | No floating tag appears in any Dockerfile. A running pod's image label resolves to a commit. |
| NFR-SEC-10 | Session cookies shall be `HttpOnly`, `Secure`, `SameSite`-constrained, and shall carry an opaque identifier only. | ADR-0006 rule 2 | MUST | Cookie attributes are asserted in test. The cookie value decodes to nothing meaningful. |
| NFR-SEC-11 | Privileged actions — publish, promote, permission grant, policy change, breaker override, refund decision, data export, tenant provisioning, **pipeline publish and activation** — shall be audited with actor, target, before and after value, and environment. | B14 tab 2; [`orchestration.md`](./orchestration.md) FR-ORCH-27 | MUST | Each action class produces an audit entry. A test enumerates the privileged-action list against the audit interceptor's coverage. |
| NFR-SEC-12 | The application shall never log unmasked PII, credentials, or full citizen transcripts. | B12 tab 1; architecture §10 | MUST | Log output for a conversation containing each PII class contains none of it. A log-scanning test runs against the E2E suite's captured output. |
| NFR-SEC-13 | Dependency and container vulnerability scanning shall run as part of the single verification command, since no scheduled pipeline exists. | ADR-0008; [`risks.md`](./risks.md) RISK-002 | MUST | `pnpm verify` and `make verify` each include a dependency and image scan, and fail on a finding above the agreed severity. |
| NFR-SEC-14 | The system shall enforce a Content Security Policy on both the backoffice and the embeddable widget that restricts script and connection sources to the configured origins. | B10 tab 2; [`channels.md`](./channels.md) FR-CHAN-09 | MUST | The widget loaded on an allowlisted origin functions; inline script injection is refused by policy. The policy is asserted in test, not only configured. |

## 7.2 Performance — `PERF`

Targets are taken from the wireframe's own observability figures (B14 tab 3). The Sharjah Services Gateway at 240 ms p95, Graph RAG retrieval at 310 ms p95 and the WhatsApp BSP at 190 ms p95 are treated as the healthy baseline the system must hold; the SEWA bill API's 1,840 ms is the *degraded* example and is therefore a breaker trigger, not a target.

| ID | Requirement | Source | Pri | Acceptance criteria |
|---|---|---|---|---|
| NFR-PERF-01 | Graph RAG hybrid retrieval, including reranking, shall complete within a p95 of 350 ms per query at the tenant's configured top-K. | B14 tab 3 (310 ms) | MUST | Load test at the expected concurrency reports p95 ≤ 350 ms. Breach is an alertable condition and appears as `Degraded` in observability. |
| NFR-PERF-02 | An MCP tool invocation shall complete within a p95 of 300 ms, excluding the upstream service's own processing beyond its configured budget. | B14 tab 3 (240 ms) | MUST | Measured p95 ≤ 300 ms against the seeded gateway. Exceeding the dependency's configured budget contributes to breaker trips ([`tools.md`](./tools.md) FR-TOOL-13). |
| NFR-PERF-03 | Channel egress to the WhatsApp BSP shall complete within a p95 of 250 ms. | B14 tab 3 (190 ms) | MUST | Measured p95 ≤ 250 ms. Breach degrades to the configured queue-and-retry fallback rather than blocking the turn. |
| NFR-PERF-04 | The system shall treat an external dependency exceeding 1,500 ms p95 or 5% error rate as degraded, tripping its breaker per configuration. | B14 tab 3; B5 tab 4 | MUST | The seeded SEWA bill API figures (1,840 ms, 6.1%) produce `Degraded` and an open breaker. Thresholds are configurable per dependency. |
| NFR-PERF-05 | The assistant shall emit its first token within a p95 of 2,000 ms of turn submission, and shall show the processing state within 300 ms. | A3; ADR-0001 | MUST | Measured p95 time-to-first-token ≤ 2,000 ms for the canonical journey. **[ASSUMPTION]** — the wireframe specifies no conversational latency target; this one is set against the "Still thinking…" state it does specify. A pipeline-governed turn (§5.5.2) is held to the same budget; live-streaming is scope-trimmed to the single-node, in-degree-≤1, owning-entity case, matching the legacy honest scope trim. |
| NFR-PERF-06 | Backoffice read screens shall render their first meaningful content within a p95 of 1,000 ms, and interactive controls shall respond within 100 ms. | architecture §9 | SHOULD | Measured against the seeded fixtures for all 14 screens. B9's 7×8 matrix and B1's explorer are included, since they are the densest. |
| NFR-PERF-07 | Backoffice list and table endpoints shall be paginated server-side and shall not degrade super-linearly with tenant data volume. | architecture §9 | MUST | A tenant with 100,000 conversations serves the explorer's first page within the NFR-PERF-06 budget. No endpoint returns an unbounded collection. |
| NFR-PERF-08 | A re-index job shall run without degrading conversational latency beyond the targets in NFR-PERF-01 and NFR-PERF-05. | ADR-0001 | MUST | Run a full re-index for one tenant under conversational load; retrieval and first-token p95 remain within budget. This is the justification for the two-runtime split and must be demonstrated. |
| NFR-PERF-09 | `shj3-web` shall scale on CPU and `shj3-ai` on concurrency, independently, with at least two replicas of each. | ADR-0008 | MUST | Both HPAs are configured with their stated metrics. Load on one does not scale the other. |
| NFR-PERF-10 | Store connections and client handles shall be pooled per tenant with a bounded ceiling, so tenant count cannot exhaust store resources. | ADR-0002 consequences | MUST | With 20 provisioned tenants under load, SQL Server connection count and Qdrant client count stay within their configured ceilings. Exceeding the ceiling queues rather than failing the process. |

## 7.3 Accessibility — `A11Y`

Target: **WCAG 2.1 Level AA**, on both the citizen and staff surfaces.

| ID | Requirement | Source | Pri | Acceptance criteria |
|---|---|---|---|---|
| NFR-A11Y-01 | The system shall conform to WCAG 2.1 AA on every citizen-facing and backoffice screen. | Project rules; ADR-0007 | MUST | An automated audit over all 17 screens plus the theming, guide and Pipeline Designer modules reports no AA violation, and a manual keyboard-and-screen-reader pass covers the wizard, the permission matrix, the graph explorer, the rule editor and the pipeline canvas. |
| NFR-A11Y-02 | Every interactive control shall be operable by keyboard alone and shall show a visible focus indicator. | guide §7.4 | MUST | Every control in the seeded journeys is reachable and operable by keyboard. Focus is never trapped except in a modal, which returns focus on close. |
| NFR-A11Y-03 | Status shall never be conveyed by colour alone; every badge, state and result shall carry a text label. | guide §7.4 | MUST | All badge states — `Active`, `Draft`, `Live`, `Blocked`, `Passed`, `Failed`, `Healthy`, `Degraded`, `Open`, `Closed` — carry text. A greyscale render remains fully interpretable. |
| NFR-A11Y-04 | Text and non-text contrast shall meet AA, validated at theme-save time rather than by inspection. | ADR-0007 | MUST | [`theming.md`](./theming.md) FR-THEME-16 blocks a non-conformant text pair. A conformant theme passes the automated audit. |
| NFR-A11Y-05 | The system shall honour `prefers-reduced-motion`, suppressing non-essential animation and transition. | guide §7.4 | MUST | With the preference set, streaming indicators, graph transitions and preview animations are static or minimal. |
| NFR-A11Y-06 | Dynamic content — streaming assistant output, queue changes, job status, validation errors — shall be announced to assistive technology through appropriate live regions. | A2, A3; B6 tab 3 | MUST | A screen reader announces a completed assistant turn, a new queue item and a failed re-index without the user navigating to find them. |
| NFR-A11Y-07 | Every list, table and canvas shall provide accessible empty, loading, error and permission-denied states. | guide §8 (gap closed) | MUST | Each state is reachable in test for every list surface, carries a text explanation and a next action, and is announced. This closes the wireframe's "empty and error states" gap. The pipeline canvas's own empty state (zero nodes) is included. |
| NFR-A11Y-08 | Data visualisations shall provide an accessible non-visual equivalent. | B1 tab 1 | MUST | The channel-split chart and the KPI panels expose their underlying figures as a table or as accessible text. |

## 7.4 Internationalisation — `I18N`

| ID | Requirement | Source | Pri | Acceptance criteria |
|---|---|---|---|---|
| NFR-I18N-01 | The system shall support English and Arabic across the citizen surface, the backoffice and the user guide, with no user-visible string hardcoded in a component. | B10 tab 5; Phase F | MUST | A string-extraction check finds no literal user-visible text in feature code. Both locales render every screen. |
| NFR-I18N-02 | The system shall render right-to-left correctly for Arabic, using logical CSS properties throughout, on both the citizen and staff surfaces. | ADR-0007; guide §8 (gap closed) | MUST | Arabic renders the assistant thread, sidebar, wizard strip, tables, the graph explorer and the pipeline canvas mirrored. No physical direction property exists in the codebase. |
| NFR-I18N-03 | The system shall measure translation completeness per locale from the message catalogue and shall expose it as the figure the publish gate consumes. | B10 tab 5; [`evaluation.md`](./evaluation.md) FR-EVAL-15 | MUST | Adding an untranslated string lowers the reported percentage without a manual edit, and the gate's decision changes accordingly. |
| NFR-I18N-04 | The system shall bind text direction to locale selection so a language change and a direction change are one action. | Phase E | MUST | Selecting Arabic sets RTL; selecting English sets LTR. There is no state in which the locale and the direction disagree. |
| NFR-I18N-05 | The system shall format dates, times, numbers and currency per locale, and shall store all timestamps in UTC. | B1, B11 tab 4 | MUST | Stored timestamps are UTC; rendered timestamps are in the tenant's configured timezone. Currency renders with an explicit code and locale-appropriate separators. |
| NFR-I18N-06 | The system shall render a missing translation in the designated fallback locale and shall count the miss. | B10 tab 5; [`channels.md`](./channels.md) FR-CHAN-19 | MUST | A missing Arabic string renders in the fallback locale, is visibly not an error, and increments a miss counter available to the localisation surface. |
| NFR-I18N-07 | Retrieval and reranking shall be effective in Arabic as well as English, measured as a first-class quality dimension. | ADR-0004; B13 tab 1 | MUST | The Arabic language parity golden set is scored on every regression run and is subject to the same publish-gate thresholds as English sets. |
| NFR-I18N-08 | Locale-specific voice selection shall apply to text-to-speech output. | B10 tab 5; [`conversation.md`](./conversation.md) FR-CONV-04 | SHOULD | An Arabic conversation uses the configured Arabic voice; an English conversation the English voice. |

## 7.5 Observability — `OBS`

| ID | Requirement | Source | Pri | Acceptance criteria |
|---|---|---|---|---|
| NFR-OBS-01 | The system shall emit OpenTelemetry traces from both runtimes with one trace id spanning web → ai → tool call → store. | architecture §10; ADR-0001 | MUST | A single citizen turn produces one trace covering both runtimes and every downstream call. B14 tab 3's figures derive from this data. |
| NFR-OBS-02 | Every log line, trace and metric shall carry the tenant, the environment and, where applicable, the conversation and agent identifiers. | ADR-0002 | MUST | Telemetry is filterable by tenant. No telemetry record lacks a tenant attribute except for platform-level operations, which carry the platform marker. |
| NFR-OBS-03 | Telemetry shall carry no PII and no credential. | NFR-SEC-12 | MUST | A scan over captured telemetry from the E2E suite finds neither. Trace attributes carrying tool arguments are masked ([`tools.md`](./tools.md) FR-TOOL-19). |
| NFR-OBS-04 | The system shall expose p95 latency and error rate per external dependency as the source for the observability screen. | B14 tab 3 | MUST | The four seeded dependencies report live figures. Removing a dependency's telemetry makes its row report "no data", never a stale figure. |
| NFR-OBS-05 | Both runtimes shall expose liveness, readiness and startup probes, with `shj3-ai` given a startup budget that accommodates model client initialisation. | ADR-0008 | MUST | An aggressive probe configuration is demonstrably rejected: `shj3-ai` starts without a restart loop under the shipped values. |
| NFR-OBS-06 | The system shall record per-model-call token counts, cost and provider against tenant, agent and conversation. | ADR-0004 rule 5 | MUST | Every model call produces a cost record. Cost is queryable per tenant, per agent and per conversation for any period. |
| NFR-OBS-07 | The system shall record every guardrail decision, refusal, degradation and fallback with its reason, so a withheld answer can always be explained. | B12; [`knowledge.md`](./knowledge.md) FR-KNOW-14 | MUST | For a refused turn, the trace names the policy, the measured confidence and the threshold. For a degraded turn, it names the missing capability. |
| NFR-OBS-08 | The system shall record re-index, purge, migration, campaign-send and outbox reconciliation job runs with scope, counts and outcome. | [`knowledge.md`](./knowledge.md) FR-KNOW-16; [`governance.md`](./governance.md) FR-GOV-27 | MUST | Each job type produces a run record. A failed run is visible and retried, never silently absent. |
| NFR-OBS-09 | The system shall expose a health endpoint per runtime reporting the reachability of each of its four stores and each configured model provider. | architecture §10 | SHOULD | With Qdrant unavailable, the AI service's health output names it. The endpoint requires authentication and returns no configuration detail. |

## 7.6 Data — `DATA`

| ID | Requirement | Source | Pri | Acceptance criteria |
|---|---|---|---|---|
| NFR-DATA-01 | SQL Server shall be the only system of record; Neo4j and Qdrant shall hold derived data only and shall be fully rebuildable from SQL Server plus the original source material. | ADR-0003 rule 1 | MUST | Drop both derived stores for a tenant and rebuild by re-index; retrieval, citations and graph traversal return to their prior state with no data loss. |
| NFR-DATA-02 | Redis shall hold only data whose loss is acceptable, and shall not be backed up. | ADR-0003 rule 2 | MUST | Flushing Redis loses active session state and resets breakers but destroys no record. A test flushes Redis mid-suite and asserts no record loss. |
| NFR-DATA-03 | Prisma shall be the sole owner of the SQL Server schema; no second migration tool shall exist in the repository. | ADR-0005 | MUST | The repository contains no Alembic or other migration tooling. All schema changes, including the Pipeline Designer's five new models, originate as a Prisma migration. |
| NFR-DATA-04 | SQLAlchemy models in `shj3-ai` shall be generated from the Prisma schema and shall never be hand-edited; drift shall fail the verification gate. | ADR-0005 rules 3, 4 | MUST | Regenerating the models produces an empty diff. Hand-editing a generated model fails the pre-commit drift check. The generated file carries a do-not-edit header. |
| NFR-DATA-05 | `shj3-ai` shall hold write permission on exactly three table groups — conversation turns, orchestration traces, re-index job status — enforced by database grant. | ADR-0005 rule 5 | MUST | An attempted write to any other table by the AI service's database user fails at the database, not in application code. The grant is asserted by a test that queries the permission catalogue. |
| NFR-DATA-06 | Transcript retention shall be configurable at 30 days, 90 days, 1 year or 7 years, defaulting to 90 days, applying to transcripts and derived memory. | B14 tab 4 | MUST | Enforced by [`governance.md`](./governance.md) FR-GOV-23 and FR-GOV-27. Data beyond the configured period is absent from all four stores after a purge run. |
| NFR-DATA-07 | Transaction records shall be retained for seven years irrespective of the transcript retention setting, as a structural carve-out rather than a configurable exception. | B14 tab 4 `[rule]` | MUST | Enforced by [`payments.md`](./payments.md) FR-PAY-08 and [`governance.md`](./governance.md) FR-GOV-24. No configuration value shortens transaction retention below seven years. |
| NFR-DATA-08 | PII shall be masked before persistence, never on read, in every store. | B12 tab 1; architecture §10 | MUST | Stored transcripts, trace tool arguments, vector payloads and graph attributions contain no unmasked PII. Verified by a scan over the stores after the E2E suite. |
| NFR-DATA-09 | Writes shall be ordered system-of-record first, then derived stores, through an outbox with a reconciliation job, and no distributed transaction shall be attempted. | ADR-0003 rule 4 | MUST | Enforced by [`knowledge.md`](./knowledge.md) FR-KNOW-25. A derived-write failure leaves the system of record correct and the outbox item pending. |
| NFR-DATA-10 | SQL Server and Neo4j shall be backed up per tenant; Qdrant shall be documented as rebuildable rather than backed up. | ADR-0008 follow-up | MUST | A per-tenant restore of both stores is demonstrated in the runbook. Qdrant recovery is the re-index path (NFR-DATA-01). |
| NFR-DATA-11 | Monetary values shall be stored as exact decimals with an explicit currency, never as floating-point. | B11 tab 4 | MUST | The schema declares a decimal type with defined precision. A round-trip of AED 412.00 is exact. |
| NFR-DATA-12 | Erasure shall be provable per tenant and per citizen across all four stores, with a per-store completion report. | B14 tab 4; ADR-0002 | MUST | Enforced by [`governance.md`](./governance.md) FR-GOV-22. The report names all four stores and lists any record retained under statutory obligation with the obligation cited. |

## 7.7 Operations — `OPS`

| ID | Requirement | Source | Pri | Acceptance criteria |
|---|---|---|---|---|
| NFR-OPS-01 | The system shall ship multi-stage, non-root Docker images for both runtimes, each with a health check and a version label. | ADR-0008 | MUST | Both images build reproducibly, run as non-root, declare a health check and carry a label resolving to a commit. |
| NFR-OPS-02 | A single `docker compose up` shall bring up both runtimes, the worker, and all four stores, seeded deterministically with at least two provisioned tenants. | ADR-0008 | MUST | From empty volumes the stack becomes healthy unattended, and the isolation suite can run against it. Local development is not a reduced configuration. **Note:** the `apps/web` container's generated Prisma client and `.next` build cache live on container-only volumes separate from the host bind mount; a schema change or a large batch of new route files landing mid-session requires `docker compose exec web npx prisma generate` and/or a `.next` cache clear plus `docker compose restart web` — both real, live-diagnosed incidents during the Pipeline Designer delivery. |
| NFR-OPS-03 | The system shall ship one Helm chart with values per environment for `development`, `uat` and `production`, mirroring the environments in the product. | ADR-0008; B14 tab 1 | MUST | The three value sets deploy. The environment names in the chart match those in [`governance.md`](./governance.md) FR-GOV-12 exactly. |
| NFR-OPS-04 | Every deployment shall declare resource requests and limits, with `shj3-ai` given substantially larger limits than `shj3-web`. | ADR-0008 | MUST | No container runs without requests and limits. The AI service's limits exceed the web service's, per ADR-0001's justification. |
| NFR-OPS-05 | Secrets shall be referenced by name from Kubernetes secrets and shall never appear in the chart or in values files. | ADR-0008 | MUST | A scan of the chart and all values files finds no secret value. The chart references secret names only. |
| NFR-OPS-06 | The system shall define pod disruption budgets and a rolling update strategy that does not drop in-flight conversation turns. | ADR-0008 | MUST | A rolling update under conversational load completes with no turn lost; in-flight turns finish on the draining pod. |
| NFR-OPS-07 | Quality gates — format, lint, typecheck, module-boundary check, schema-drift check and unit tests — shall run as mandatory pre-commit hooks, and shall be present in the first commit. | ADR-0008; project rules | MUST | Each gate is present and blocking. Bypassing hooks is a documented policy violation, and [`risks.md`](./risks.md) RISK-002 records the resulting exposure. |
| NFR-OPS-08 | One command — `pnpm verify` and `make verify` — shall run the full gate: lint, typecheck, unit, integration, E2E and security scan. | ADR-0008 | MUST | Each command runs the complete gate and returns a single pass/fail. "Green" has exactly one meaning. |
| NFR-OPS-09 | The test suite shall be written CI-ready: no manual steps, no interactive prompts, deterministic seeds, containerised dependencies. | ADR-0008; Phase D | MUST | The suite runs unattended from a clean checkout. Adding a pipeline later requires a configuration file, not a test refactor. **The Pipeline Designer is a known exception as of this delivery** — its domain logic is unit-tested but it has no Playwright E2E spec yet; see [`risks.md`](./risks.md) RISK-026. |
| NFR-OPS-10 | Releases shall be produced by a scripted, versioned process that builds and tags both images with the same version; a manual local build shall not be a release path. | ADR-0008 | MUST | The release script produces both images with identical versions and pushes them. Image labels trace to the commit. |
| NFR-OPS-11 | Module boundaries shall be enforced mechanically in both runtimes: a feature module importing another feature module's internals shall fail the gate. | architecture §3; ADR-0001 rule 4 | MUST | The boundary linters are configured for all 17 wireframe modules plus the Pipeline Designer's `pipeline-*`-prefixed files inside `orchestration`. An added cross-feature import fails the check. |
| NFR-OPS-12 | Domain and application layers shall contain zero vendor imports in either runtime, verified mechanically. | architecture §4 | MUST | A search of `domain/` and `application/` for vendor package names returns nothing in both runtimes, including the Pipeline Designer's `domain/pipeline.py`, `domain/condition_expr.py` and `apps/web`'s `domain/pipeline-*.ts`. Replacing a vendor adapter touches no domain file — the swap test. |
