# 5.7 `knowledge` — Graph RAG (B6)

Runs in `shj3-ai`. Satisfies brief requirement R6. `shj3-web` never opens a graph or vector connection (ADR-0003).

| ID | Requirement | Source | Pri | Acceptance criteria |
|---|---|---|---|---|
| FR-KNOW-01 | The system shall maintain a knowledge source registry recording name, type, owning entity, crawl schedule, indexed percentage and last-crawled time. | B6 tab 1 | MUST | The four seeded sources render with all six fields. Indexed percentage reflects actual chunk coverage, not a stored constant. |
| FR-KNOW-02 | The system shall add a source given a name, a location or URL, a type from `Document`, `URL crawler`, `Database`, `SharePoint`, `API feed`, and a schedule from `Manual`, `Daily`, `Weekly`. | B6 tab 1 | MUST | All five types and three schedules are selectable and persisted. A newly added source begins at 0% indexed with an ingestion job queued. |
| FR-KNOW-03 | The system shall re-crawl a source on demand, updating its indexed percentage and last-crawled time on completion. | B6 tab 1 | MUST | Re-crawling drives the source to its true coverage and sets last-crawled to the completion time. The operation is asynchronous with observable job status (FR-KNOW-16), not a synchronous request. |
| FR-KNOW-04 | The system shall remove a source, deleting its chunks from the system of record, its vectors from Qdrant and its derived entities from Neo4j where no other source supports them. | B6 tab 1 | MUST | After removal no retrieval cites the source. Entities supported by another remaining source survive; entities supported only by the removed source are deleted. |
| FR-KNOW-05 | The system shall surface indexing state per source rather than implying that a saved source is immediately retrievable. | ADR-0003 consequences; B6 tab 1 | MUST | A source at 70% indexed displays that figure, and retrieval over it is possible but reported as partial. The UI never shows a saved-but-unindexed source as ready. |
| FR-KNOW-06 | The system shall maintain an entity graph generated from indexed data, supporting the entity types `Service`, `Provider`, `Fee`, `Document`, `Channel` and the relationship types Service→Provider, Service→Fee, Service→Document, Fee→Channel. | B6 tab 2 | MUST | The graph renders from the node/edge data model, not from static markup; adding a node appears immediately. All five entity types and four relationship types are representable and traversable. |
| FR-KNOW-07 | The system shall expose, on selecting a graph node, its type, its label, its connected nodes and the sources that support it. | B6 tab 2 | MUST | Selecting the `Service(Pay utilities bill)` node lists its Provider, Fee and Document neighbours and names the sources that grounded them. |
| FR-KNOW-08 | The system shall filter the graph by entity search, de-emphasising non-matching nodes as the query is typed. | B6 tab 2 | MUST | Typing a partial entity name narrows the visible set live. Clearing the query restores the full graph. Filtering is client-side over the loaded subgraph and does not alter stored data. |
| FR-KNOW-09 | The system shall detect candidate duplicate entities and offer merge or ignore for each candidate, recording the decision. | B6 tab 2 | MUST | The two seeded candidates render. Merging redirects all edges and citations to the surviving entity with no dangling reference; ignoring suppresses the candidate from future detection until its supporting data changes. Both are audited. |
| FR-KNOW-10 | The system shall add a graph entity manually given a label and a parent, placing it, creating the edge, and making it immediately inspectable. | B6 tab 2 | MUST | A manually added node is queryable by search, appears in traversals, and is marked as manually authored rather than source-derived. |
| FR-KNOW-11 | The system shall configure retrieval with chunk size, chunk overlap, embedding model, hybrid graph/vector weighting, top-K passages and a reranker toggle. | B6 tab 3 | MUST | Defaults are 512 tokens, 64 tokens overlap, `text-embedding-3-large`, 60/40 graph/vector, top-K 8, reranker on. Every value is per tenant and takes effect on the next retrieval. |
| FR-KNOW-12 | The system shall expose hybrid weighting as a continuous control with a live numeric label, and the configured weighting shall govern the ranking actually applied. | B6 tab 3 | MUST | Moving the control to 80/20 changes the displayed label and demonstrably changes the ranking returned by the playground for the same query. |
| FR-KNOW-13 | The system shall record the embedding model and vector dimension on each vector collection, shall warn that changing the embedding model requires a full re-index, and shall trigger a full re-index rather than saving the preference alone. | ADR-0004 rule 3; B6 tab 3 | MUST | Changing the model presents an explicit confirmation naming the consequence and enqueues a full re-index job. Vectors produced by two different embedding models never coexist in one collection — asserted by a check on the collection metadata. |
| FR-KNOW-14 | The system shall degrade rather than fail when reranking is unavailable, returning hybrid-ranked results unreranked and recording the degradation. | ADR-0004 rule 6 | MUST | With the reranker provider unavailable, retrieval still returns results, the turn still completes, and the trace records that reranking was skipped. A rerank outage never fails a citizen conversation. |
| FR-KNOW-15 | The system shall provide a retrieval playground that, for an entered query, returns ranked passages with numeric scores and the matched subgraph. | B6 tab 3 | MUST | For "pay SEWA bill" the playground returns scored passages and the matched path `Service(Pay utilities bill) → Provider(SEWA) → Fee`. Playground runs use the tenant's live retrieval configuration. |
| FR-KNOW-16 | The system shall maintain a re-index job history with per-job status of `Running`, `Completed` or `Failed`, and shall re-index all sources on demand. | B6 tab 3 | MUST | Triggering a re-index adds a `Running` job that resolves to a terminal state. A failed job records the failing source and the reason. Job status is one of the three table groups `shj3-ai` may write (ADR-0005 rule 5). |
| FR-KNOW-17 | The system shall resolve every citation through the system of record, so that a stale vector payload cannot produce a citation to content that no longer exists. | ADR-0003 rule 3 | MUST | Delete a chunk from the system of record and leave its vector in place; retrieval must not cite it. Every citation shown to a citizen or in the playground is backed by a live chunk row. |
| FR-KNOW-18 | The system shall detect a source conflict when two indexed sources return contradicting values for the same graph entity, and shall record both sides with their source, value and last-updated time. | B6 tab 4 `[rule]` | MUST | The two seeded conflicts are detected and rendered with both values, both sources and both update times. A newly ingested contradicting value raises a new conflict without manual action. |
| FR-KNOW-19 | The system shall support a default conflict-resolution policy selected from `Prefer most recently updated source`, `Prefer owning entity source`, and `Always ask an admin`, applied per tenant. | B6 tab 4 | MUST | Each of the three policies is selectable and changes which value grounds an answer for an unresolved conflict. `Always ask an admin` withholds an authoritative value until a human resolves it. |
| FR-KNOW-20 | The system shall resolve a conflict when an administrator marks one side authoritative, and subsequent answers shall ground on that side. | B6 tab 4 | MUST | Marking the SEWA tariff schedule authoritative removes the conflict from the queue, restores grounding confidence for touching answers, and is audited with actor, entity and chosen side. |
| FR-KNOW-21 | The system shall lower the grounding confidence of any answer touching an unresolved conflict, by an amount sufficient to be capable of tripping the configured refusal threshold. | B6 tab 4 `[rule]`; B12 | MUST | An answer grounded on a conflicted entity reports lower confidence than the same answer after resolution. With the refusal threshold at 60% and a conflicted entity, the answer is withheld and a human is offered. |
| FR-KNOW-22 | The system shall not rely on recency alone to resolve conflicts: the owning-entity and ask-an-admin policies shall be available and shall produce the correct outcome where the more recent source holds the less authoritative value. | B6 tab 4 `[rule]` | MUST | For the library-membership conflict — where the more recent source is the less authoritative one — `Prefer most recently updated source` selects the wrong value and `Prefer owning entity source` selects the Library membership policy. Both outcomes are asserted, because the failure of the recency policy is the point of the test. |
| FR-KNOW-23 | The system shall be able to rebuild Neo4j and Qdrant in full from the system of record plus the original source material, using the same re-index mechanism exposed in the product. | ADR-0003 rule 1 | MUST | Drop both derived stores for a tenant, run re-index, and retrieval quality and citations return to their prior state. No separate recovery tool is required. |
| FR-KNOW-24 | The system shall ground answers only on sources belonging to the tenant serving the conversation. | ADR-0002; B6 tab 1 | MUST | A retrieval executed in tenant A returns no passage, entity or citation from tenant B, verified across both derived stores. Covered by the isolation gate in [`tenant-isolation.md`](./tenant-isolation.md). |
| FR-KNOW-25 | The system shall order writes system-of-record-first, then derived stores, using an outbox with a reconciliation job, and shall never attempt a distributed transaction across stores. | ADR-0003 rule 4 | MUST | Fail a derived write; the system of record remains correct, the outbox retains the pending item, and reconciliation or re-index repairs the index. No two-phase commit exists in the codebase. |
| FR-KNOW-26 | An unresolved source conflict shall reduce the grounding confidence of every answer touching the affected entity, by an amount capable of tripping the configured refusal policy, and resolving the conflict shall restore it. | `knowledge` → `governance`; B6 tab 4 → B12 | MUST | With the tariff conflict unresolved and the threshold at 60%, a tariff question is refused and a human offered. Mark one side authoritative: the same question is answered. The confidence figure and the refusal decision are recorded on both traces. *(Cross-module invariant; also listed in [`cross-module.md`](./cross-module.md).)* |
