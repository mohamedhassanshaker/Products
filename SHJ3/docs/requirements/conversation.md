# 5.3 `conversation` — assistant surface, turns, transcripts (A1, A2, A3)

| ID | Requirement | Source | Pri | Acceptance criteria |
|---|---|---|---|---|
| FR-CONV-01 | The system shall render the assistant widget in a docked state and an expanded state and shall retain thread contents and scroll position across a state change. | A1 states | MUST | Toggling docked → expanded → docked preserves every message and the scroll offset. Neither state navigates away from or reloads the host portal page. |
| FR-CONV-02 | The system shall display a dismissible disclaimer banner stating that responses may not be fully accurate, with text supplied by channel configuration. | A1 components; B10 tab 2 | MUST | The banner renders on first open, dismisses on ×, stays dismissed for the session, and its text comes from the widget studio field rather than from code. |
| FR-CONV-03 | The system shall render a greeting message and a configurable set of suggestion chips resolved from Quick Actions configuration, and shall not hardcode chip labels or targets. | A1 components; B7 message node | MUST | Editing a Quick Action changes the rendered chips with no deploy. The five seeded chips match the brief. Tapping a chip posts a turn equivalent to the user typing that text. |
| FR-CONV-04 | The system shall display, per message, a text-to-speech control and a timestamp, and on assistant messages thumbs-up and thumbs-down controls. | A1, A2 message meta | MUST | All four controls are present and keyboard reachable. TTS uses the locale voice configured in B10 tab 5. |
| FR-CONV-05 | The system shall provide a composer with a configurable placeholder and a microphone control. | A1 components; B10 tab 2 | MUST | Placeholder text comes from configuration. The mic control is disabled with a machine-readable reason when voice input is unavailable. |
| FR-CONV-06 | The system shall render the transcript as an accumulating, chronologically ordered thread in which user and assistant turns are distinguished semantically, not only visually. | A2 | MUST | After four turns all four are present in order. Speaker is conveyed by markup and text, never by alignment or colour alone. |
| FR-CONV-07 | The system shall record and expose, per turn, an agent trace holding the routing decision with its confidence, every tool invoked with its arguments, every secondary agent consulted, and the pending slot if any. | A2 diagnostics rail | MUST | For the canonical journey the step-3 trace contains `router → billing_agent`, `get_bill_status(provider="SEWA")` and `awaiting slot: account_number`. Traces are persisted, not merely rendered. When a pipeline is active, the trace additionally carries the pipeline fields in [`orchestration.md`](./orchestration.md) §5.5.2. |
| FR-CONV-08 | The system shall expose, per grounded turn, the retrieval sources used — source document, freshness, and the entity path traversed — and shall state explicitly when no grounding was required. | A2 sources panel | MUST | Step 1 reports that no grounding was needed for a static template. Step 3 names the SEWA tariff schedule and the traversed entity path. Every cited source resolves to a real chunk in the system of record ([`knowledge.md`](./knowledge.md) FR-KNOW-17). |
| FR-CONV-09 | The system shall accept voice input and shall display an interim transcription preview before commit so the user can correct it. | A3 states | MUST | Interim text is marked as not yet sent. Committing sends the corrected text; abandoning sends nothing. A recording indicator is present while capture is active. |
| FR-CONV-10 | The system shall display a processing state while a turn is being generated and shall stream assistant output as it is produced. | A3 states; ADR-0001 | MUST | The processing indicator appears within 300 ms of submission and clears on first token. Output streams over SSE rather than arriving as one block. |
| FR-CONV-11 | The system shall display an escalated state showing queue position and confirming context transfer, and shall pause the composer while a human holds control. | A3 states | MUST | On escalation the banner names the queue position, the composer is disabled with an explanatory label, and the state clears when the human agent releases or closes the conversation. |
| FR-CONV-12 | The system shall record thumbs-up and thumbs-down feedback against the specific turn and shall make thumbs-down entries available to the feedback queue. | A1, A2; B1 tab 3 | MUST | A rating is stored with turn id, conversation id, tenant, channel and timestamp. A thumbs-down appears in the B1 tab 3 queue. |
| FR-CONV-13 | The system shall mask PII — at minimum Emirates ID, account numbers and card numbers — before a transcript or derived memory is persisted, never on read. | B12 tab 1; architecture §10 | MUST | Insert a turn containing each PII class; the stored row contains only the masked form. No code path can read an unmasked stored transcript because none was written. |
| FR-CONV-14 | The system shall record a conversation outcome of `Resolved`, `Escalated` or `Abandoned` according to a documented derivation rule. | B1 tab 2 | MUST | `Escalated` when a handover ticket is created; `Abandoned` when a session expires with an unanswered assistant prompt outstanding; `Resolved` otherwise. **[ASSUMPTION]** — the wireframe shows the values but not their derivation. |
| FR-CONV-15 | The system shall preserve conversation context across a free-text escape so an interrupted flow can be resumed. | A2 step 4 `[rule]` | MUST | After escaping the billing flow and asking an unrelated question, the pending `account_number` slot and all prior turns remain available, and returning to billing does not restart the flow. |
| FR-CONV-16 | The system shall scope every conversation session to one tenant and one channel, resolved at session creation, and shall reject any turn whose claimed tenant differs from the session's. | ADR-0002 rule 1 | MUST | A forged tenant on a turn payload is ignored in favour of the session's tenant. A cross-tenant turn injection returns 403 and writes no data. |
